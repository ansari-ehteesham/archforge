## What I Learned

### Guardrails

- With `--rerun` false, nothing calls the embedding API. `--query` creates the orchestrator object, which makes no API call, and then embeds only the one question.
- In a retry loop with `range(retries)`, the last attempt is `retries - 1`, so the check to stop must use `retries - 1`.

## What I Implemented

- `--rerun` argument: false by default. False means the full pipeline never runs.
- `--query` argument: queries the stored ChromaDB collection (top 5 results with documents, metadata and distances) so I can evaluate the RAG.
- Batch upload in `store_data` (20 chunks per batch, 20 s wait, retry after 60 s, upsert).

## Problems / Errors

### Problem 1

A failed batch could be skipped silently: `if attempt == retries` never runs inside `range(retries)`.

### Cause

The last attempt number is `retries - 1`.

### Resolution

Use `if attempt == retries - 1: raise`. Check the `store_data` result in the orchestrator. (Confirm applied.)

### Problem 2

With `--rerun` false and no `--query`, the CLI did nothing and printed nothing.

### Resolution

Print a short "nothing to do" message. (Confirm applied.)
